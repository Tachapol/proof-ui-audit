# ProofUI Critique Studio

Open http://localhost:3123/studio while `npm run dev` is running.

## Workflow
1. Choose Website URL and enter a public HTTP(S) page, or select Demo frames. For a local development page, explicitly enable Allow this localhost target. Localhost opt-in is enabled only when ProofUI runs in development mode; LAN and metadata addresses remain blocked.
2. Enter Product Goal, Brand Keywords, Theme Color, Target Audience and Others.
3. Select AI perspectives: User Experience, Product Vision and Engineering.
4. Start critique. Code audits the rendered DOM/CSS first; the CPE model reviews the supplied evidence and context. Lead Coordinator summarizes the agenda.
5. Select a finding, inspect evidence, ask a selected role a question, and accept or reject the finding.
6. For eligible text contrast findings, choose a six-digit color and use Preview & measure.
7. Apply becomes available only when the measured contrast, horizontal overflow and target geometry checks pass. Apply changes the saved session preview; Revert restores the original preview.
8. Use History to resume a session or export JSON/Markdown.

## Scope and interpretation
- Studio supports public website URLs and explicitly opted-in loopback URLs in local development, focusing on text contrast. It also retains the two controlled demo frames. It does not import Figma frames.
- URL audits capture the rendered page at 375, 1440 and 320 px. Studio displays an audit-time image rather than embedding a live third-party frame; the original page remains available via Open original. Sites requiring login or blocking browser automation may fail or produce partial results, which are shown.
- For website URLs, apply changes in your own source and run another critique. Automatic Preview/Apply remains limited to supported controlled demo fixtures.
- AI roles are perspectives generated by the configured model, not independent human experts. Partial provider failures are shown explicitly.
- Complex backgrounds remain Needs review and do not get an automatic color correction.
- Agenda ordering supports discussion; it is not the proposal research metric-ranking result.
- Preview checks do not establish full WCAG conformance, usability, task success or conversion improvement.
- Original source files are not rewritten by Apply. Session data is stored locally under `.proofui-data/studio`; screenshot artifacts are under `public/screenshots`.
- Provider credentials stay in server-side environment variables. Do not place keys in source code or reports.
